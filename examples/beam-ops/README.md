# BEAM OPS

Tactical operations desktop application for the Beam sensor network.

Built with Electron + React + TypeScript + MapLibre GL JS.

---

## Prerequisites

- Node.js 20+
- npm 9+
- Beam daemon running on `localhost:9091`

---

## Quick Start

### 1. Install dependencies

```bash
cd beam-ops
npm install
```

The `postinstall` script automatically rebuilds `better-sqlite3` for the installed Electron version.

### 2. Download map tiles (optional but recommended)

```bash
npm run tiles:create
```

This downloads CARTO Dark Matter tiles for the Hood River, OR area (zoom levels 8–15) into `tiles/hood-river.mbtiles`. Takes a few minutes (~100ms delay between requests). Without tiles the map will show a dark background only.

### 3. Start in development mode

```bash
npm run dev
```

### 4. Build for production

```bash
npm run build
npm run preview
```

## Architecture

### Process Model

```
Electron Main Process
├── tile-server.ts    — Express on :3002, reads MBTiles with better-sqlite3
├── IPC handlers      — Proxy Beam API calls to localhost:9091
└── BrowserWindow     — Hosts renderer

Preload Script
└── contextBridge     — Exposes window.beamApi and window.tileApi

Renderer Process (React)
├── BeamController    — Manages daemon connection and workspace lifecycle
├── MapView           — MapLibre GL map, uses tile server at :3002
├── BeamStatus        — Floating tactical status overlay (bottom-left)
├── PayloadFeed       — Live SSE payload tail (right side)
└── WorkspaceSelector — Workspace selection modal
```

### Why IPC for Beam API calls?

The Beam daemon at `localhost:9091` has CORS restricted to `localhost:3001`. All API calls are proxied through the Electron main process via IPC, bypassing CORS entirely.

### Why a local tile server?

MapLibre GL JS runs in the renderer process (Chromium) and cannot directly read SQLite files. The tile server (`better-sqlite3` + Express) runs in the main process and serves tiles over HTTP at `localhost:3002`.

## App Flow

1. App starts → `BeamController.initialize()`
2. Daemon offline → error card with retry button
3. Not signed in → "not authenticated" error card
4. No active workspace → `WorkspaceSelector` modal (full-screen overlay)
5. User selects workspace → `BeamController.activateWorkspace(id)`:
   - `POST /api/device/connect` (connect USB node, non-fatal if fails)
   - `POST /api/workspace/activate`
6. Main operational view: map + tactical overlays

---

## Tile Server

- Port: `3002`
- Endpoint: `GET /tiles/:z/:x/:y` → PNG or 204
- Health: `GET /health`
- MBTiles TMS→XYZ conversion: `tms_y = (1 << z) - 1 - y`

---

## IPC Channels

| Channel | Direction | Description |
|---|---|---|
| `beam:health` | invoke | Boolean — daemon reachable |
| `beam:auth-state` | invoke | Auth state from daemon |
| `beam:system` | invoke | System info |
| `beam:workspaces` | invoke | List workspaces |
| `beam:activate-workspace` | invoke | Activate workspace by ID |
| `beam:device-connect` | invoke | Connect USB node |
| `beam:horizon-devices` | invoke | List mesh devices |
| `beam:identities` | invoke | List identities |
| `beam:payloads` | invoke | Recent payloads |
| `beam:tail-payloads` | send | Start SSE tail |
| `beam:stop-tail` | send | Stop SSE tail |
| `beam:payload-event` | receive | Incoming payload from tail |
